Database schema

02

SQLite, migrated by raw CREATE TABLE IF NOT EXISTS statements plus a small additive-column patcher in server/db/schema.ts (currently schema version 3). Every table uses a TEXT id primary key (UUIDs), except the two purchase-history tables keyed on Kroger's own identifiers.

Why two schemas Kroger's public API has no order-history endpoint. Item-level history only exists in kingsoopers.com's internal web endpoints, captured by hand from the browser console (see docs/purchase-history.md) and imported separately — so this domain has no foreign key back into the meal-planning core. The only bridge is canonical_name, matched in application code, not the database.

Purchase-history import flow

03

Kroger's public API has no order-history endpoint, so this data is captured by hand from kingsoopers.com's internal web endpoints, then imported and optionally enriched against the official Products API. See docs/purchase-history.md for the full capture scripts.
